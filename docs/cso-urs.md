**项目名称**：云漫智企（CloudStrollOffice）
**版本号**：v0.0.1（初始化基线，对应已实现能力 v0.1.6）

## 1. 业务目标
本版本（v0.0.1 初始化基线）以"企业统一认证授权 + 办公套件基础服务"为核心业务目标，为云漫智企微服务办公套件建立可运行、可扩展的基础底座，具体目标如下：

1. **建立企业统一认证中心**：提供 4 种登录模式（用户名密码/手机验证码/手机+密码/OAuth）与 5 种注册模式（用户名密码/手机验证码/OAuth/手机号设用户名/OAuth 补全信息），支持两步注册（先注册后补全信息），覆盖企业员工、外部用户、第三方账号等全部登录场景，认证能力可通过策略工厂模式持续扩展。
2. **实现多租户 RBAC 权限模型**：基于用户-角色-权限三层关联模型实现细粒度访问控制，租户间数据完全隔离，用户名在租户内唯一，权限按树形结构组织，满足多企业共平台运营需求。
3. **构建安全可靠的会话认证体系**：采用 JWT RS256 非对称签名双 Token 机制（Access Token 2 小时 + Refresh Token 7 天 + 轮换机制），结合 Redis 登录态会话、Token 黑名单与账号/租户状态缓存，实现主动登出、强制踢人实时生效。
4. **实现网关统一认证入口**：API 网关统一拦截全部请求，通过 9 步校验流程（白名单放行、Bearer 格式校验、RS256 公钥验签、Token 类型校验、黑名单校验、登录态校验、账号状态校验、租户状态校验、Header 透传）保障后端服务安全，业务服务无需重复实现认证逻辑。
5. **完善账号自服务能力**：提供密码修改/密码找回、手机号变更（原手机可用→短信验证，原手机停用→邮箱验证）、验证码管理（生成/发送/校验/频率控制）等自助功能，降低企业管理成本。
6. **建立安全审计能力**：全量记录登录日志（登录 IP、客户端类型、登录结果、失败原因），为安全事件追溯与合规审计提供数据支撑。
7. **搭建办公套件服务骨架**：提供企业服务（企业信息/人事管理骨架）、系统服务（系统配置/日志/监控/定时任务骨架）与健康检查链路，为后续 v0.2.0+ 企业/部门/员工、工作流审批、薪酬管理等业务功能奠定微服务基础。

量化指标：认证服务覆盖 4 种登录模式、5 种注册模式、6 种客户端类型；RBAC 模型支撑 9 张业务表；单元测试 200+ 全部通过；认证核心接口（登录/注册/刷新）响应时间 P95 ≤ 500ms。

## 3. 业务场景
### 3.1 多模式登录
- **触发条件**：用户访问办公套件任一受保护资源且当前无有效登录态。
- **参与角色**：普通员工、OAuth 第三方用户、访客（登录场景）、企业管理员。
- **操作流程**：用户在登录页选择登录模式（用户名密码/手机验证码/手机+密码/OAuth）→ 输入对应凭证（密码或验证码或跳转第三方授权）→ 选择客户端类型（Windows/Ubuntu/H5/Android/iOS/WeChatMini）与租户 → 提交登录 → 认证服务按对应登录策略校验凭证（手机验证码模式先通过验证码管理器校验验证码）→ 校验通过后签发 JWT 双 Token（Access Token 2h + Refresh Token 7d）→ 在 Redis 建立登录态会话并记录登录日志 → 返回 Token 供客户端使用。

### 3.2 多端混合登录与会话管理
- **触发条件**：同一账号在多个设备/客户端登录，或管理员需要强制下线某用户。
- **参与角色**：普通员工、企业管理员。
- **操作流程**：系统支持 6 种客户端类型（Windows/Ubuntu/H5/Android/iOS/WeChatMini）同端互斥、多端共存——同一客户端类型新登录会踢掉旧会话，不同类型客户端可同时在线 → 每次登录在 Redis 建立独立会话 → 用户主动登出时将该 Token 加入黑名单并清除会话 → 管理员通过强制踢人接口将指定用户全部登录态实时失效 → 密码找回重置后系统自动清除该账号全部登录态。

### 3.3 多租户隔离与权限管理
- **触发条件**：平台存在多个企业租户，管理员需要为用户配置访问权限。
- **参与角色**：系统管理员、企业管理员。
- **操作流程**：系统管理员维护租户与平台权限树 → 企业管理员在本租户内创建角色（租户内编码唯一）→ 为角色分配权限（树形选择）→ 创建用户并分配角色 → 用户登录后仅能访问其角色关联权限范围内的资源 → 租户间数据不可见，用户名仅需在租户内唯一。

### 3.4 用户注册与两步注册
- **触发条件**：访客首次使用系统需要创建账号。
- **参与角色**：访客/未登录用户、普通员工。
- **操作流程**：用户选择注册模式（用户名密码/手机验证码/OAuth）→ 按模式提交注册信息（用户名密码模式需符合密码策略，手机验证码模式需先获取并填写验证码，OAuth 模式跳转第三方授权）→ 系统校验租户、用户名唯一性等信息 → 创建账号（OAuth 模式自动关联第三方账号）→ 若信息不完整则进入两步注册第二步：登录后通过"完善账号信息"接口补全用户名/密码/手机号 → 账号补全后可正常使用全部功能。

### 3.5 密码找回与修改
- **触发条件**：用户忘记密码需要重置，或出于安全考虑需要更换密码。
- **参与角色**：普通员工、访客/未登录用户。
- **操作流程**：修改密码：登录后提交旧密码与新密码 → 系统校验旧密码正确性与新密码策略 → 更新密码并记录最后修改时间。找回密码：未登录用户选择目标（手机号/邮箱）与模式（SMS/EMAIL）→ 发送验证码 → 输入验证码与新密码 → 系统校验验证码（60 秒发送频率控制、5 分钟有效期）→ 重置密码并自动清除该账号全部登录态。

### 3.6 手机号变更
- **触发条件**：员工更换手机号，需要更新账号绑定手机。
- **参与角色**：普通员工。
- **操作流程**：登录后提交原手机号、新手机号与验证码 → 系统按场景校验：原手机可用时通过短信验证码验证，原手机停用时通过邮箱验证码验证 → 校验通过后更新绑定手机号 → 变更后涉及验证码类登录/找回的通道自动切换到新手机号。

### 3.7 验证码管理
- **触发条件**：登录、注册、密码找回、手机号变更等场景需要短信/邮箱验证码。
- **参与角色**：普通员工、访客/未登录用户。
- **操作流程**：用户提交目标（手机号/邮箱）与用途（登录/注册/找回密码/变更手机号）→ 系统检查发送频率（同一目标 60 秒内不可重复发送）→ 生成 6 位数字验证码（有效期 5 分钟）并发送（模拟模式直接返回固定验证码供开发调试，真实模式通过短信/邮件服务商发送）→ 用户提交验证码 → 系统校验验证码有效性、用途匹配与生命周期 → 校验通过后继续后续业务。

### 3.8 登录日志审计
- **触发条件**：登录成功或失败时自动记录；管理员需要追溯安全事件。
- **参与角色**：普通员工、企业管理员、系统管理员。
- **操作流程**：每次登录请求（无论成功失败）自动写入登录日志（登录 IP、客户端类型、登录结果、失败原因、时间戳）→ 管理员通过日志数据追溯异常登录、暴力破解等安全事件 → 失败原因（密码错误、验证码错误、账号禁用、租户禁用等）支撑安全分析。

## 6. 约束条件
1. **技术栈约束**：后端必须基于 Java 21（LTS）+ Spring Boot 3.2.5 + Spring Cloud 2023.0.1 + MyBatis-Plus 3.5.6 实现，采用 Maven 多模块工程（公共/网关/认证/企业/系统 5 个模块），客户端基于 Flutter 开发。
2. **微服务架构约束**：必须保持模块间低耦合，公共代码统一放 cloudoffice-common；服务间通过 Nacos 2.3.0 注册发现与 API 网关统一路由（端口：网关 9000、认证 9100、企业 9200、系统 9400）。
3. **中间件依赖约束**：必须依赖 MariaDB 10.6 关系型数据库（认证库 9 张表，企业/系统库预留）与 Redis 7.2.x 缓存（登录态/黑名单/状态缓存），外部服务不可用时认证功能不可用。
4. **密钥管理约束**：JWT RS256 需要 RSA 2048 位密钥对，私钥仅认证服务使用，公钥供网关验签；密钥通过环境变量（RSA_PRIVATE_KEY/RSA_PUBLIC_KEY）注入，禁止提交到代码仓库（keys/ 目录已 gitignore）。
5. **多租户隔离约束**：所有业务数据必须按租户隔离，用户名仅要求租户内唯一，禁止跨租户访问数据。
6. **接口规范约束**：REST 接口路径统一为 /api/v1/{module}/{resource}，全部接口统一返回 ApiResult 响应体，统一错误码与全局异常处理。
7. **安全约束**：密码必须满足最小 8 位、最大 64 位的策略并通过 BCrypt 加密；验证码必须受频率控制与有效期约束；认证/权限失败统一返回规范化错误结构。
8. **时间约束**：本版本为初始化基线版本，功能范围限定为已实现的统一认证授权与办公套件基础服务能力，企业/人事/系统业务仅提供骨架。

## 7. 假设与依赖
1. **外部服务依赖**：假设 Nacos 2.3.x（注册中心）、MariaDB 10.6（数据库）、Redis 7.2.x（缓存）在部署环境中可用且已正确配置连接（DB_HOST/DB_PORT/DB_USERNAME/DB_PASSWORD/REDIS_HOST/REDIS_PORT 等环境变量）。
2. **密钥依赖**：假设部署前已通过 OpenSSL 生成 RSA 2048 位密钥对并配置 RSA_PRIVATE_KEY/RSA_PUBLIC_KEY 环境变量。
3. **验证码模拟模式**：开发/演示环境默认开启验证码模拟模式（VERIFICATION_CODE_MOCK=true，直接返回固定验证码 123456）；真实短信/邮件发送依赖外部服务商接入，生产环境需配置真实发送通道。
4. **OAuth 提供商依赖**：OAuth 登录/注册依赖第三方平台（微信、钉钉、GitHub 等）授权服务可用及对应的应用凭证配置。
5. **初始数据假设**：假设初始化脚本已执行，包含默认租户 DEFAULT、超级管理员角色 SUPER_ADMIN、管理员账号 admin（默认密码 admin123，生产环境需修改）及基础权限数据。
